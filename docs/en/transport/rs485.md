# BiDiB over RS-485 (BiDiBus)

This document describes how to use the BiDiB Arduino library with an RS-485 bus, as specified by BiDiBus.

## 1. Overview

The BiDiBus uses an RS-485 physical layer for robust, high-speed communication. A key characteristic of this bus is that a master node controls bus access. Slave nodes can only transmit data after being polled by the master.

This library provides the `BiDiB_RS485` class to handle the specific requirements of the BiDiBus, including direction control for the RS-485 transceiver and a queuing mechanism for outgoing messages.

## 2. Hardware Setup

-   **Arduino Board:** Any Arduino-compatible board with a hardware serial port.
-   **RS-485 Transceiver:** A standard RS-485 transceiver module (e.g., based on the MAX485 chip).
-   **Connections:**
    -   Connect the transceiver's `DI` (Driver Input) to the Arduino's `TX` pin.
    -   Connect the transceiver's `RO` (Receiver Output) to the Arduino's `RX` pin.
    -   Connect the transceiver's `DE` (Driver Enable) and `RE` (Receiver Enable) pins together to a digital output pin on the Arduino. This will be the direction control pin.

## 3. Using the `BiDiB_RS485` Class

The `BiDiB_RS485` class inherits from the standard `BiDiB` class and handles the bus-specific logic automatically.

### Initialization

To use the class, you need to include `BiDiB_RS485.h` and create an instance, providing the pin number for the direction control.

```cpp
#include <BiDiB_RS485.h>

const int RS485_DE_PIN = 4; // The pin connected to the DE/RE pins of the transceiver

BiDiB_RS485 bidib(RS485_DE_PIN);

void setup() {
  // BiDiBus operates at 500 kbaud
  Serial1.begin(500000);
  bidib.begin(Serial1);

  // ... rest of your setup
}
```

### Sending Messages

When you call a function that sends a message (e.g., `bidib.logon()`, `bidib.sendOccupancySingle()`), the `BiDiB_RS485` class does not transmit the message immediately. Instead, it places the message into an outgoing queue.

### Polling and Transmission

In your main `loop()`, you must call both `bidib.update()` and `bidib.handleMessages()`.

-   `bidib.update()` reads incoming data from the bus byte-by-byte. It automatically detects the single-byte poll from the master and sends the next message from the queue. It also assembles any incoming messages.
-   `bidib.handleMessages()` should be called after `update()` if `bidib.messageAvailable()` is true. This method processes the content of a fully received message (e.g., to trigger callbacks).

```cpp
void loop() {
  bidib.update();
  if (bidib.messageAvailable()) {
    bidib.handleMessages();
  }

  // ... your application logic
}
```

This ensures that your node only transmits when it has permission from the master, complying with the BiDiBus protocol.
